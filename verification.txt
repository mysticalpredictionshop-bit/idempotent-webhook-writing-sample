What this establishes
- Repeated matching delivery leaves one receipt and one counter increment
- A second simultaneous writer receives SQLITE_BUSY with timeout=0; retry
  after the first commit returns duplicate without another increment
- An injected exception immediately before COMMIT rolls back both writes
- Reusing an event ID for changed payload is rejected without a second effect
- Distinct event IDs count separately; unknown tickets leave no receipt
- Incompatible connection modes are rejected; a caller's open transaction
  is not rolled back by the handler

Limits
This is a new original educational sample. No client deployment, production
load, power failure, process kill, hostile request, HTTP endpoint, remote API,
email delivery, or multi-machine database arrangement was tested. The example
requires authenticated, validated input and retained receipts in one database.
It is not a complete webhook server or security audit. No performance or
end-to-end exactly-once delivery claim is made.
